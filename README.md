# New York Quarterly ED Demand App

An end-to-end healthcare analytics and forecasting project for New York
facility-county emergency department demand. The original DATA 975 Flask / ML
project is preserved, with the data-preparation layer refactored into Oracle SQL
and an additional Power BI reporting layer.

## Live application

https://ny-quarterly-ed-demand-app.onrender.com/

## What changed from the original project

The original notebook performed acquisition, cleaning, aggregation, joins,
feature engineering, EDA, modeling, and evaluation in one Python/Colab flow.
The revised portfolio version separates responsibilities:

```text
Raw public-data CSVs
        |
        v
Oracle raw tables
        |
        v
Oracle SQL
clean -> aggregate -> join -> feature engineering -> QA
        |
        +------------------------------+
        |                              |
        v                              v
FINAL_COUNTY_QUARTER_ANALYSIS    BI_COUNTY_QUARTER_METRICS
        |                              |
        v                              v
Python notebook                    Power BI
EDA + ML + evaluation              dashboard / KPIs
        |
        v
model artifacts
        |
        v
Flask application
```

This avoids duplicating data-cleaning logic in Python while keeping the original
model-selection, evaluation, and Flask deployment workflow.

## Forecasting design retained from the original project

The application compares:

- tuned XGBoost;
- previous-quarter persistence;
- same-quarter previous-year persistence.

The final analysis recommends previous-quarter persistence for the one-quarter-
ahead prototype and retains XGBoost for historical evaluation.

The application intentionally remains focused:

- **Main page:** choose one facility county and one period.
- **Prototype forecast:** uses the notebook's recommended method.
- **Historical result:** shows observed demand, XGBoost, and persistence benchmarks.
- **Multi-county evaluation:** compares XGBoost with previous-quarter persistence.
- **Limitations banner:** prevents retrospective results from being interpreted as
  a live current-quarter staffing feed.

## Project scope

- Unit: one New York facility county-quarter
- Target: total ED encounters
- Historical target period: 2018-2024 in the SQL-prepared analytical panel
- Selected ML family: XGBoost
- Benchmarks: previous-quarter and seasonal persistence
- Operational recommendation from the original final evaluation: previous-quarter persistence
- Purpose: retrospective planning prototype, not a live staffing feed

## Interpretation

Skill is the percentage reduction in MAE relative to the strongest persistence
benchmark. Positive skill favors the candidate model; negative skill favors the
simpler benchmark.

## Limitations

- Facility county is not necessarily the patient's county of residence.
- Public suppression may understate totals in affected facility county-quarters.
- The final holdout is historical rather than a live prospective staffing feed.
- External predictors are intentionally lagged to avoid using unavailable future
  information.
- Pooled R² is secondary to out-of-time MAE, WAPE, and skill because county demand
  differs greatly in scale.
