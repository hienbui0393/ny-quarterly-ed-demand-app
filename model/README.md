# Model Artifacts

This folder contains only trained-model artifacts used by the Flask application.
The processed county-quarter dataset now lives in `data/processed/`, not in this
folder.

## Files

### `quarterly_ed_xgboost_model.json`

Portable XGBoost model generated by `notebooks/ed_demand_modeling.ipynb`.
Do not edit this file manually. The copy included in this starter package comes
from the original working project and will be overwritten when you rerun the
SQL-refactored modeling notebook.

### `quarterly_ed_forecast_artifact.joblib`

Generated by the notebook after the final model is evaluated. It contains the
ordered feature list, target definition, selected method, scaler when required,
validation metrics, and deployment metadata. It is intentionally not included
in this starter package; generate it by running the notebook.

## Processed application data

The Flask app loads the SQL-prepared panel from:

`data/processed/county_quarter_analysis.csv`

That CSV must be exported from Oracle from `FINAL_COUNTY_QUARTER_ANALYSIS` after
running the validation checks in `sql/01_build_county_quarter_analysis.sql`.

## After rerunning the pipeline

1. Run and validate the Oracle SQL pipeline.
2. Export `FINAL_COUNTY_QUARTER_ANALYSIS` to
   `data/processed/county_quarter_analysis.csv`.
3. Run `notebooks/ed_demand_modeling.ipynb` locally.
4. Confirm these files are generated together:
   - `model/quarterly_ed_xgboost_model.json`
   - `model/quarterly_ed_forecast_artifact.joblib`
5. Run `python tests/smoke_test.py`.
6. Run `python app.py` and verify `/health`.

The processed panel and model artifacts should come from the same pipeline
version so their feature definitions stay synchronized.
