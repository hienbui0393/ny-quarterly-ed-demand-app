# Model and Supporting Data

This folder contains the trained forecasting model and the supporting files loaded by the Flask application.

## Files

### `quarterly_ed_xgboost_model.json`

The trained XGBoost model.

This file contains the decision trees and learned model parameters used to generate quarterly emergency department demand forecasts.

Do not edit this file manually.

### `quarterly_ed_forecast_artifact.joblib`

Supporting deployment information exported from the final notebook.

Depending on the current notebook version, this artifact may contain items such as:

- the ordered feature-column list;
- the target variable name;
- model settings;
- training-period information;
- validation results;
- other metadata required by the Flask application.

The actual XGBoost model is stored separately in `quarterly_ed_xgboost_model.json`.

### `county_quarter_analysis.csv`

The processed county-quarter analysis panel used by the application.

The Flask app uses this file to:

- populate available county selections;
- retrieve historical county data;
- construct lag and rolling features;
- determine available forecast periods;
- provide historical context for the forecast.

This is processed application data, not the original raw dataset.

## After Retraining the Model

When the final model is retrained:

1. Export a new `quarterly_ed_xgboost_model.json`.
2. Export a matching `quarterly_ed_forecast_artifact.joblib`.
3. Export the current `county_quarter_analysis.csv` if the processed panel changed.
4. Replace the old files in this folder.
5. Keep the filenames unchanged unless the paths in `app.py` are also updated.
6. Run the application tests:

   ```bash
   python tests/smoke_test.py
   ```

7. Start the Flask app locally:

   ```bash
   python app.py
   ```

8. Verify the health endpoint:

   `http://127.0.0.1:5000/health`

The model, artifact, and processed data should come from the same final notebook run so that their feature definitions remain synchronized.

## Important

Do not place the following items in this folder or commit them to GitHub:

- API keys or passwords;
- `.env` files;
- raw or unnecessarily large datasets;
- virtual-environment folders;
- temporary notebook files.
